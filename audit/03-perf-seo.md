# Частина 1. Продуктивність

## 1.1. Зображення

| Файл | Розмір | Габарити | Де використовується | Вердикт |
|---|---|---|---|---|
| `img/hero.jpg` | **1 479 KB** 🔴 | 1760×1176, 300 DPI | hero `<img>` (index.html:131) + фон CTA (index.html:670) | LCP-елемент. Потрібен WebP ≈ 180–250 KB |
| `img/og-image.jpg` | 215 KB 🟠 | 1200×630 | лише og/twitter meta — на сторінці не рендериться | стиснути до ~90 KB (`-q 80`) |
| `img/logo.jpg` | 126 KB 🟠 | 1070×1070 | header 52px (eager) + footer 48px (lazy) | замінити на WebP/PNG 128×128 ≈ 6 KB (−95%) |
| `favicon.png` | 24 KB 🟡 | — | favicon + apple-touch-icon | можна стиснути, не пріоритет |

**Разом ~1.85 MB картинок, з них ~1.6 MB вантажиться при відкритті сторінки** (hero + logo). Після оптимізації: ~200 KB. Це найбільший перфоманс-резерв сайту.

### WebP + `<picture>` — так, потрібен (для hero)

```html
<link rel="preload" as="image" href="img/hero.webp" type="image/webp" fetchpriority="high" /> <!-- у <head> -->

<picture>
  <source srcset="img/hero.webp" type="image/webp" />
  <img src="img/hero.jpg" alt="Склад вантажних шин MF Tires Hub у Києві"
       class="w-full h-full object-cover" loading="eager" fetchpriority="high"
       width="1760" height="1176" />
</picture>
```

Команди конвертації:
```bash
cwebp -q 78 img/hero.jpg -o img/hero.webp          # ~200 KB
cwebp -q 80 -resize 128 128 img/logo.jpg -o img/logo.webp   # ~5 KB
cwebp -q 80 img/og-image.jpg -o /dev/null  # OG лишити JPEG! месенджери не всі їдять webp;
# натомість перезберегти jpg: jpegtran/squoosh з quality 80 → ~90 KB
```

⚠️ Для og:image **залишити JPEG** — Telegram/Viber/WhatsApp надійно прев'юють саме jpg/png.

### loading="lazy" нижче hero — вже майже все зроблено ✅

Растрових зображень нижче першого екрана лише два, і обидва вже ок: footer-лого `loading="lazy"` (index.html:703), Maps iframe `loading="lazy"` (index.html:657). Решта графіки — інлайн-SVG, їх лейзити не треба. **Додавати нічого.**

### width/height проти CLS — ризик низький

- header-лого: `width="52" height="52"` ✅ (index.html:83)
- footer-лого: `width="48" height="48"` ✅ (index.html:703)
- hero `<img>`: атрибутів немає, **але** він `absolute inset-0` у секції `min-h-screen` — розмір задає контейнер, CLS не виникає. Додати width/height все одно варто (безкоштовно).

Реальні дрібні джерела CLS: (а) FOUT від `font-display: swap` — Oswald помітно інших пропорцій за системний фолбек; (б) лічильники, що міняють «0»→«5000» (ширина stat-бейджа стрибає). Обидва — у межах норми.

## 1.2. Google Maps iframe — вже лазі, але варто фасад

Iframe **не вантажиться одразу**: стоїть `loading="lazy"` (index.html:657) ✅. Однак нативний lazy спрацьовує заздалегідь (за ~1–2 екрани до в'юпорта в Chrome), і користувач, що доскролив до контактів, все одно тягне **~1.2–1.5 MB** скриптів Google Maps — на мобільному 4G це відчутно.

**Рекомендація — клік-плейсхолдер (фасад):** статичне зображення карти + кнопка «Відкрити карту», iframe створюється лише по кліку. Готовий сніпет: [snippets/maps-facade.html](snippets/maps-facade.html). Бонус: до кліку немає запитів до Google → менше cookie-трекінгу.

Компромісний мінімум (без зміни UX): лишити як є — `loading="lazy"` вже рятує первинне завантаження.

## 1.3. Скрипти — рендер не блокують, але два болти підкрутити

- `js/ui.js`, `js/animations.js`, `js/flip.js` (разом ~6 KB) підключені **в кінці `<body>` без defer** (index.html:793–795). Початковий рендер вони не блокують (DOM уже розпарсений), але парсер таки зупиняється на них в самому кінці. Рекомендація: додати `defer` — браузер скачає їх паралельно ще на початку парсингу. Дрібний, безкоштовний виграш.
- 🔴 Що реально блокує рендер: **битий `<link href="css/tailwind.css">`** (index.html:63) — файла не існує, браузер чекає 404-відповідь до першого рендера (детально в [01-structure.md](01-structure.md), К1). Видалити рядок.
- Сторонніх скриптів немає (ні аналітики, ні чат-віджетів) — з перфоманс-погляду чудово. (Якщо конверсія = дзвінок, варто колись додати легку аналітику кліків по tel: — але це бізнес-рішення.)

## 1.4. Шрифти

- Джерело: Google Fonts, два сімейства — **Oswald** (400;500;600;700) + **Nunito** (400;500;600;700) = до 8 woff2-файлів (~120–160 KB разом, лише латиниця+кирилиця по факту використання).
- `display=swap` ✅ є в URL (index.html:68) — текст видимий одразу, FOUT замість FOIT.
- `preconnect` до обох доменів fonts.googleapis.com / fonts.gstatic.com ✅ (index.html:66–67).
- Резерв: **Oswald 400 ніде не використовується** (у CSS Oswald завжди 500/600/700) — можна прибрати з URL, мінус один файл. Перевірити й Nunito 500 (використовується лише в інлайн-стилях фліп-беків).
- Опційно: self-host шрифтів (woff2 у репо) — мінус DNS+TLS до двох доменів, повний контроль кешу. Для GitHub Pages працює добре. Не критично.

# Частина 2. SEO

## 2.1. meta keywords — прибрати ✅ так

`index.html:11` містить ~700 символів укр+рос ключів. Факти:
- Google **офіційно ігнорує** meta keywords з 2009 року; Bing трактує як можливий спам-сигнал.
- Тег **зливає семантичне ядро конкурентам** — вони бачать, на які запити ви цілитесь, одним View Source.
- Російськомовні ключі в коді україномовного сайту нічого не дають: для ранжування за рос. запитами потрібен контент, а не мета-тег.

**Вердикт: видалити рядок повністю.** Семантику відпрацьовувати контентом (заголовки, тексти секцій) — он вона вже частково там: «вантажний шиномонтаж», «ремонт шин» у h3.

## 2.2. Structured data — переробити поточний JSON-LD

Поточний блок (index.html:33–60) непоганий, але має **критичну помилку**: `"openingHours": "Mo-Su 08:00-20:00"`, тоді як реальний графік (підтверджений вами) — **Пн–Пт 9:00–18:00**. Google показує години прямо у видачі/картах: клієнт приїде в суботу до зачинених воріт.

Також: тип `["AutoRepair", "Store"]` можна точніше — `AutoPartsStore` (схеми `TireShop` у schema.org не існує, AutoPartsStore — найближчий легальний тип) у комбінації з `AutoRepair`. Додані `geo` (координати витягнуті з вашого ж maps-embed: 50.4167967, 30.4093055), `openingHoursSpecification`, `hasMap`.

**Готовий блок: [snippets/jsonld-localbusiness.html](snippets/jsonld-localbusiness.html)** — замінити ним index.html:33–60.

⚠️ Не забути синхронізувати графік у двох інших місцях: фліп-картка «Режим роботи» (index.html:415–421 — там уже правильно Пн–Пт 9–18) і текст «Ми на зв'язку щодня» (index.html:589 — суперечить).

## 2.3. robots.txt + sitemap.xml — згенеровано

Обох файлів немає. Готовий вміст: [snippets/robots.txt](snippets/robots.txt) і [snippets/sitemap.xml](snippets/sitemap.xml) — покласти в корінь репозиторію (поруч з index.html). Після деплою: додати сайт у Google Search Console й відправити sitemap вручну — для односторінника це найшвидший шлях до переіндексації.

## 2.4. Заголовки h1–h3

Ієрархія **валідна**: один h1 → п'ять h2 → h3 у картках, без пропусків рівнів. Зміст:

| Рівень | Текст | Оцінка |
|---|---|---|
| h1 (index.html:145) | «Вантажні шини високої якості» | ✅ головний ключ є; ⚠️ немає гео «Київ» — він лише в бейджику над h1 звичайним текстом |
| h2 | «Наші послуги», «Наші переваги», «Способи доставки», «Контакти», «Потрібна консультація?» | 🟡 всі генеричні, нуль ключів |
| h3 services | «Нові вантажні шини», «Вживані шини», «Диски», «Ремонт шин», «Вантажний шиномонтаж» | ✅ найкращі ключі сторінки сидять саме тут |

Рекомендації (без фанатизму, сторінка не перенасичена):
- h1: «Вантажні шини **в Києві**» або додати гео в підзаголовок-абзац — найдешевший локальний сигнал.
- h2 «Наші послуги» → «Послуги: продаж і ремонт вантажних шин» — один h2 з ключем достатньо, решту можна не чіпати.

## 2.5. Лічильники «0+» очима краулера 🔴

Без виконання JS (текстовий парсер, AI-краулери, месенджер-прев'ю, скрейпери каталогів) сторінка містить буквально:

> «**0**+ шин в наявності · **0**+ років досвіду · **0**+ задоволених клієнтів»

Googlebot рендерить JS, але: (а) рендер-черга може відпрацювати з затримкою в дні; (б) count-up стартує по IntersectionObserver — на headless-рендері з нестандартним в'юпортом не гарантований; (в) усі інші споживачі HTML (Bing у деяких режимах, GPT/Claude-краулери, прев'ю-боти) бачать «0+». Фікс описаний у [02-uiux.md](02-uiux.md) К1: у статичному HTML — фінальні числа, JS сам обнуляє перед анімацією.

## 2.6. alt-тексти для локального SEO

Растрових зображень всього 3, всі з alt ✅, але без гео-сигналів:

| Рядок | Зараз | Рекомендація |
|---|---|---|
| index.html:83 | `alt="MF Tires Hub логотип"` | ок, лишити |
| index.html:131 | `alt="Склад вантажних шин MF Tires Hub"` | → `«Склад вантажних шин MF Tires Hub у Києві»` — головна картинка сторінки, гео тут найдоречніше |
| index.html:703 | `alt="MF Tires Hub"` | ок (футер-дубль лого, можна навіть `alt=""`) |

Інлайн-SVG-іконки всі `aria-hidden="true"` ✅ — правильно, alt їм не потрібен.

## 2.7. Дрібні SEO-прогалини (бонус)

- Немає `<meta property="og:locale" content="uk_UA" />` — 1 рядок.
- Немає `og:image:width/height` (1200/630) — прискорює перший шеринг (месенджер не качає картинку для визначення розмірів).
- `lang="uk"` ✅, canonical ✅, twitter:card ✅ — база на місці.
- 404.html відсутня (див. [01-structure.md](01-structure.md) В1).
