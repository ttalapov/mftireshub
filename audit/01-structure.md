**Дата:** 2026-06-11
**Об'єкт:** односторінковий лендинг, GitHub Pages, домен mftireshub.pp.ua
**Обсяг:** index.html (798 рядків, 69 KB), css/ (28 KB), js/ (12 KB), img/ (1.8 MB)

## 🔴 Критичні знахідки (виправити в першу чергу)

### К1. Бите підключення `css/tailwind.css` — файл не існує

`index.html:63`:
```html
<link rel="stylesheet" href="css/tailwind.css" />
```

Файлу `css/tailwind.css` **немає в репозиторії** — в `css/` лежить лише `main.css`.
Кожне завантаження сторінки робить запит, який повертає 404 (GitHub Pages віддає HTML-сторінку помилки).

**Наслідки:**
- зайвий блокуючий запит у `<head>` → уповільнення рендеру;
- 404 у консолі/мережі — мінус до Lighthouse Best Practices.

**Чому сайт при цьому виглядає нормально:** скомпільований Tailwind (v3.4.19, мініфікований, з preflight) вже **вшитий у початок `css/main.css`** — тобто стилі дублюватися й не мали, просто посилання застаріло.

**Фікс:** видалити рядок 63 з `index.html`. Один рядок, нульовий ризик.

### К2. `img/hero.jpg` — 1.5 MB, це LCP-елемент

1760×1176, baseline JPEG, щільність 300 DPI (зайва для вебу). Це фонове зображення hero — найбільший елемент першого екрана (LCP). 1.5 MB на мобільному 4G — це +3–5 с до завантаження. Для лендингу, де конверсія — дзвінок з телефона, це пряма втрата клієнтів.

**Фікс (без зміни верстки):**
```bash
# WebP ~150-250 KB замість 1.5 MB
cwebp -q 78 img/hero.jpg -o img/hero.webp
# + стиснутий jpg як фолбек
```
У HTML hero вставлений через `<img>` (index.html:131) — можна обгорнути в `<picture>` з webp + jpg. Також варто додати `<link rel="preload" as="image">` у head, бо це LCP.

⚠️ `hero.jpg` використовується вдруге як фон CTA-секції (index.html:670, `bg-[url('img/hero.jpg')]`) — там він прихований на 90% (opacity-10), браузер закешує, але при заміні на webp не забути обидва місця.

### К3. Розбіжність графіку роботи: Schema.org каже одне, сайт — інше

- JSON-LD (index.html:52): `"openingHours": "Mo-Su 08:00-20:00"` — щодня 8:00–20:00
- Фліп-картка «Режим роботи» (index.html:415–421): Пн–Пт 9:00–18:00, **Сб–Нд вихідний**
- Текст у контактах (index.html:589): «Ми на зв'язку щодня»

Google показує графік із Schema.org прямо у видачі. Клієнт приїде в суботу — а зачинено. Для бізнесу «конверсія = дзвінок/приїзд» це репутаційна проблема. **Треба з'ясувати у власника реальний графік і синхронізувати всі три місця.**

## 🟠 Високий пріоритет

### В1. Відсутні службові файли

Мінімальний `robots.txt`:
```
User-agent: *
Allow: /
Sitemap: https://mftireshub.pp.ua/sitemap.xml
```

### В2. logo.jpg — 126 KB на 52-піксельну аватарку

1070×1070 JPEG, відображається 52×52 (header) і 48×48 (footer). Завантажується eager у header.

- JPEG не має прозорості → лого «кругле» лише завдяки `rounded-full`, на іншому фоні буде квадрат.
- **Рекомендація:** експортувати PNG/WebP 128×128 (2x для retina) — буде ~5–10 KB, у 15+ разів менше. SVG — ідеально, якщо лого векторне в оригіналі (за метаданими робилось у Photopea — ймовірно растрове, тоді PNG/WebP).

### В3. og-image.jpg — 215 KB

1200×630 — правильний розмір для OG, але можна стиснути до ~80–100 KB без видимих втрат (`-q 80`). Вантажиться месенджерами при кожному шерингу посилання.

### С2. Tailwind: скомпільований ✅, але без можливості перезібрати

**Це НЕ CDN** — у `main.css` лежить мініфікований білд Tailwind v3.4.19 (purged, ~17 KB) + кастомні стилі (~500 рядків). Для продакшену це прийнятно: 28 KB total, ~6.8 KB gzip — чудовий розмір.

**Проблема інша:** в репозиторії немає `tailwind.config.js`, `package.json` і вихідного CSS. Додати нову утиліту (наприклад, `md:grid-cols-4`), якої немає в білді, **неможливо без повного перезбирання**, а конфіг із брендовими кольорами (`brand-red`, `brand-dark`...) втрачено.

**Рекомендація — відновити білд-ланцюжок (локальний білд + коміт результату):**

```bash
npm init -y
npm install -D tailwindcss@3.4.19

# tailwind.config.js — відновити з існуючих класів:
# colors: { 'brand-red': '#c9181e', 'brand-redlit': '#e8282f',
#   'brand-dark': '#0a0a0a', 'brand-card': '#131313',
#   'brand-border': '#222222', 'brand-muted': '#888888',
#   'brand-silver': '#c8c8c8' }
# fontFamily: { display: ['Oswald'], body: ['Nunito'] }
# content: ['./index.html', './js/**/*.js']

# src/input.css: @tailwind base; @tailwind components; @tailwind utilities;
npx tailwindcss -i src/input.css -o css/tailwind-build.css --minify
```

Або **GitHub Action** (якщо не хочеться Node локально):

```yaml
# .github/workflows/tailwind.yml
name: Build Tailwind
on:
  push:
    branches: [main]
    paths: ['index.html', 'src/**', 'tailwind.config.js']
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: npm ci
      - run: npx tailwindcss -i src/input.css -o css/tailwind-build.css --minify
      - uses: stefanzweifel/git-auto-commit-action@v5
        with: { commit_message: 'chore: rebuild tailwind css' }
```

Для поточного обсягу правок (контент, кольори) це **не терміново** — сайт працює. Стане блокером при першій спробі використати новий Tailwind-клас.

### С3. css/main.css: дублювання та дрібне сміття

- **Артефакт `-e `** наприкінці мініфікованого Tailwind-блоку (кінець рядка 6: `...line-height:1}}-e `) — слід від `echo -e` при склеюванні файлів. Браузер це мовчки ігнорує як невалідний селектор, але це маркер «крихкого» ручного процесу збирання.
- **Подвійний reset:** Tailwind preflight вже задає `box-sizing`, а кастомна частина повторює `*, *::before, *::after { box-sizing: border-box }` (рядки 20–22). Нешкідливо, але зайве.
- **Дубльована типографіка body:** `<body class="bg-brand-dark text-white font-body">` + те саме у `body {}` (рядки 28–34). Працює як подвійна страховка, але правити доведеться у двох місцях.
- Невикористаних кастомних класів **не виявлено** — всі `.nav-link`, `.btn-*`, `.flip-*`, `.tag*`, `.reveal` тощо задіяні (частина додається з JS: `reveal`, `visible`, `flipped`, `scrolled`, `open`, `nav-link--active`).
- CRLF-закінчення рядків — для GitHub Pages байдуже, просто факт.

### С4. js/: код якісний, але скрипти без `defer`

Три файли, всі в IIFE, `'use strict'`, без глобального сміття, помилок не знайдено:

| Файл | Робить | Оцінка |
|---|---|---|
| `ui.js` (91 р.) | header при скролі, бургер-меню, плавний скрол з компенсацією висоти хедера, активний пункт навігації (IntersectionObserver) | ✅ passive scroll listener, aria-expanded оновлюється |
| `animations.js` (88 р.) | scroll-reveal, стаггер по сітках (i×0.08s), лічильники count-up з easeOut | ✅ `unobserve` після спрацювання — без витоків |
| `flip.js` (30 р.) | універсальний фліп карток: клік по `.flip-trigger` → фліп, клік по картці → назад | ✅ |

Зауваження:
- Підключені в кінці `<body>` **без `defer`** (index.html:793–795). Працює коректно (DOM уже розпарсений), але `defer` у `<head>` або на поточних тегах дозволив би браузеру качати їх паралельно з парсингом. Дрібна оптимізація.
- Три HTTP-запити по ~1–3 KB — можна склеїти в один `main.js`, але на HTTP/2 виграш мізерний. Не пріоритет.
- Крихкість у `animations.js:67`: `el.childNodes[0].textContent` — лічильник пише в перший текстовий вузол. Якщо колись переформатувати HTML стат-бейджа (перенести `0` на новий рядок з відступом), зламається тихо. Безпечніше тримати число в окремому `<span>`.
